1. Technical Specifications & Value Proposition

Physical unattended printing from modern cloud web applications has historically struggled against three severe architectural and browser-level security barriers:

  • Cashier Disruption (window.print()): Freezes JavaScript execution, triggers an OS dialog requiring manual Enter keystrokes, and distorts thermal ticket widths.
  • Mixed Content Restrictions (SSL): Secure HTTPS cloud apps cannot initiate HTTP requests to http://localhost or private local network IPs.
  • Java Operational Burden (QZ Tray): Demands cumbersome client-side Java Runtime Environments (JRE) and self-signed certificate maintenance.
  • High Subscription Costs (PrintNode): Expensive recurring per-printer monthly charges.

Nyxo Universal Printer overcomes these limitations through a hybrid architecture combining a native Laravel package with a lightweight Windows agent interacting directly with the native Windows Print Spooler (winspool.drv) and SumatraPDF:

Operational Metric Traditional Solutions (Browser / QZ) Nyxo Universal Printer Solution
Dispatch Speed 3 to 8 seconds with mandatory human interaction 0.2 seconds directly to printer tray
Browser Dialogs Forced (Ctrl+P) on every ticket Zero popups (100% silent background execution)
Local SSL Certificates Required on each workstation to bypass mixed-content blocks None required (outbound HTTPS polling over port 443)
Runtime Environment Heavy Java JRE or exposed local WebSockets Native C / Win32 Spooler highly optimized binary
Development Testing Wasted thermal paper rolls on your desk Virtual on-screen emulator and interactive HTML preview

2. System Architecture & Data Lifecycle

The subsystem operates using an atomic database queue with pessimistic locking and a secure outbound long-polling protocol:

┌────────────────────────────────────────────────────────────────────────┐ │ LARAVEL WEB APPLICATION (Cloud / VPS) │ │ │ │ NyxoPrinter::to($nodeId) │ │ ->title('COFFEE SHOP') │ │ ->table($items) │ │ ->total($amount) │ │ ->cut() │ │ ->send(); │ │ │ │ 1. Compiles ESC/POS binary stream or Base64 (PDF / RAW / JSON) │ │ 2. Persists atomic payload in `print_jobs` table as 'pending' │ └───────────────────────────────────┬────────────────────────────────────┘ │ Outbound HTTPS Polling (Standard Port 443) │ Header: Authorization: Bearer <token> ▼ ┌────────────────────────────────────────────────────────────────────────┐ │ NYXO DESKTOP AGENT (Client POS PC / Cashier) │ │ │ │ - Emits heartbeat ping every 5 seconds (GET /api/v1/print/ping) │ │ - Fetches pending jobs with atomic locking (GET /jobs) │ │ - Confirms successful hardware injection (POST /status) │ └───────────────────┬───────────────────────────────┬────────────────────┘ │ winspool.drv (RAW) │ SumatraPDF (Silent CLI) ▼ ▼ ┌───────────────────────────────┐ ┌───────────────────────────────┐ │ THERMAL RECEIPT PRINTER │ │ CONVENTIONAL A4 PRINTER │ │ (ESC/POS 80mm / 58mm) │ │ (Office Laser / Inkjet) │ │ • Receipts, Kitchen Orders │ │ • Invoices, Delivery Slips │ │ • Guillotine Cut & RJ11 Kick │ │ • High quality PDF output │ └───────────────────────────────┘ └───────────────────────────────┘

State Lifecycle of a Print Job (`PrintJob`)

  1. pending: Job is queued in Laravel and awaiting pickup.
  2. processing: Local desktop agent polls GET /jobs. The database locks rows using lockForUpdate() and increments attempts.
  3. printed: Hardware spooler confirms data injection. The agent sends POST /jobs/{id}/status with status: 'printed'.
  4. failed: In case of hardware disconnection or paper jams, the agent reports status: 'failed' with error details in error_message.

Configuration on Windows Desktop Client

🔒 Clean Factory State by Default (Security & Multi-Tenant Privacy)
By strict security and multi-tenant isolation design, the official client application is distributed 100% clean and unlinked by default:
  • Zero Preloaded URLs or Tokens: Neither the SaaS server endpoint (saasUrl) nor secret terminal tokens (tenantToken) come pre-configured. The desktop application starts completely empty, waiting for operator pairing via 1-click token or manual entry.
  • Zero Preloaded Emulator Parameters (Clean Priority): The emulator and network printer address fields (emulatorUrl) start completely empty. On real production retail workstations with physical USB/Network thermal printers, this field is not used. If an emulator address is configured during development (e.g. 127.0.0.1:9100), the agent automatically activates Exclusive Emulator Mode, cleanly disabling physical thermal printer selectors and routing 100% of thermal receipt jobs to the on-screen emulator. Clearing the field instantly restores physical printers.
  • Strict Zero-License Lockout Mode: The workstation starts without an active license. As long as the terminal lacks an active, verified Lemon Squeezy license key, all agent operations and navigation tabs are strictly locked (Status, Connection, Printers, and Settings tabs are disabled with padlock indicators 🔒). The sole permitted action in the entire application is entering and activating a license key in the License tab. Once successfully activated, all views and background polling instantly unlock. All licenses (both the $0 USD Developer Free tier and commercial editions) are issued exclusively via Lemon Squeezy (https://printer.nyxo.ar).
🛡️ First Launch on Windows 10/11 (SmartScreen Notice)
When running the installer or portable version for the first time, Windows Defender SmartScreen may display a blue dialog ("Windows protected your PC"). This is standard for newly distributed binaries that do not carry costly EV enterprise code-signing certificates:

To proceed: Click "More info" and click the "Run anyway" button.

🔄 Background Daemon & System Tray Integration
Nyxo Universal Printer operates as an unattended background service:
  • Clicking the "X" button: The window does not quit; it hides to the Windows System Tray next to the clock. This prevents cashiers from accidentally closing the print daemon and halting point-of-sale receipts.
  • Restoring the window: Double-click the printer tray icon next to the clock, or simply run the .exe again (the Single Instance Lock detects the existing background instance and brings the window to the foreground immediately).
  • Exiting the application: Right-click the System Tray icon and select "Exit".

5. Complete Internal REST API Specification

All endpoints are handled by PrintJobApiController and protected by CheckPrintToken middleware:

Multi-Source Token Resolution

To prevent header stripping caused by Apache or FastCGI proxies, the middleware inspects:

  1. Headers X-Tenant-Token, X-Print-Token, Print-Token, Token.
  2. Standard Authorization: Bearer <token> header.
  3. Query or body parameters ?token= or ?print_token=.
  4. Server variables HTTP_AUTHORIZATION and REDIRECT_HTTP_AUTHORIZATION.
💡 Smart Auto-Decoding of Pairing Strings
If an operator accidentally pastes the Base64 1-Click Pairing String into a token-only field, the middleware detects the | pipe character, decodes the string, and extracts the authentic token seamlessly.

⚠️ Critical PHP 8.x Rule with Mike42/Escpos
Calling $printer->close() destructively wipes the connector buffer to null. Attempting to extract buffer data afterwards throws a fatal error implode(): Argument #1 must be of type array|string, null given. In Nyxo Universal Printer, buffer extraction is safely handled before closing inside ThermalBuilder::toBase64().

7.2 Hardware C# Emulator (ESSI Thermal Emulator)

The ESSI Thermal Emulator is an optional standalone visual simulator for developers, designed to craft receipt templates and test workflows without wasting physical thermal paper rolls.

  • Optional Testing Utility: In real cash registers and production retail stores with physical USB/Network thermal printers, the emulator is NOT installed or utilized. The desktop agent ships from factory with emulator address fields completely empty.
  • Exclusive Emulator Priority Rule (Clean UI Lock): To eliminate routing conflicts and remove the burden of unbinding physical printers during testing, the Nyxo Agent enforces an intelligent priority toggle:
    • When emulatorUrl is populated (e.g. 127.0.0.1:9100 in Settings): The agent enters Active Emulator Mode. Physical thermal printer dropdowns (80mm & 58mm) are automatically disabled in the Printers tab, and an informative blue notification banner is displayed: "Emulator Mode Active (Dev) - All thermal print jobs are automatically redirected to the emulator". 100% of ESC/POS receipt jobs route straight to the on-screen emulator.
    • When emulatorUrl is left empty: The banner is hidden and physical thermal printer selectors are restored, routing jobs to physical Windows Spooler USB printers or TCP network printers.
    • (Note: A4 document assignment remains independent and active, allowing physical laser/inkjet printing even when the thermal emulator is active).
  • Local Testing Workflow:
    1. Launch ESSI Thermal Emulator (ESSIThermalEmulator.exe), which starts a TCP/HTTP listener on port 9100.
    2. In the Nyxo Agent, navigate to the ⚙️ Settings tab, enter 127.0.0.1:9100 in the C# Emulator / TCP Socket Destination field, and click Save Settings.
    3. Jobs sent from Laravel will now render on-screen with virtual paper roll animations, 80mm/58mm width toggle, and native PDF export options.

9.3 Step 3: Host Component Listener (The Complete Solution)

When the user clicks "Print" in the modal, it emits nyxo-print-requested. The host component must listen to this event to render and enqueue the document:

namespace App\Livewire;

use Livewire\Component;
use Livewire\Attributes\On;
use App\Models\Order;
use Nyxo\Printer\Facades\NyxoPrinter;
use Nyxo\Printer\Templates\OrderSummaryTemplate;

class ManageOrders extends Component
{
    /**
     * Listen to print requests emitted from the Nyxo modal
     */
    #[On('nyxo-print-requested')]
    public function executePrint(array $payload): void
    {
        $documentId = $payload['documentId'];
        $format = $payload['format']; // 'ticket_80mm', 'ticket_58mm', 'a4'
        $printerNodeId = $payload['printerNodeId'];
        $copies = $payload['copies'] ?? 1;

        $order = Order::with('items')->findOrFail($documentId);

        if ($format === 'ticket_80mm' || $format === 'ticket_58mm') {
            NyxoPrinter::to($printerNodeId)
                ->width($format === 'ticket_58mm' ? 58 : 80)
                ->copies($copies)
                ->template(new OrderSummaryTemplate([
                    'empresa' => config('app.name'),
                    'order_number' => $order->id,
                    'fecha' => $order->created_at->format('Y-m-d H:i'),
                    'cliente' => $order->customer_name,
                    'telefono' => $order->customer_phone,
                    'equipo' => $order->device,
                    'problema' => $order->issue,
                    'reparaciones' => $order->items->map(fn($d) => [
                        'nombre' => $d->description,
                        'precio' => $d->price,
                    ])->toArray(),
                    'total' => $order->total,
                ]))
                ->send();
        } else {
            $pdf = \Barryvdh\DomPDF\Facade\Pdf::loadView('pdf.order_a4', ['order' => $order]);
            NyxoPrinter::to($printerNodeId)
                ->copies($copies)
                ->pdf(base64_encode($pdf->output()), format: 'a4')
                ->send();
        }
    }
}

10. Official Desktop Agent Guide: Operation, Configuration & Deployment

The Nyxo Universal Printer desktop agent is the native background client running locally on each cashier or Point-of-Sale (POS) terminal under Windows 10/11 (64-bit). It communicates outbound with the Laravel cloud backend and dispatches physical jobs to printers with zero open inbound router ports, zero client SSL certificates, and zero Java virtual machine dependencies.

10.1 Distribution Modes: Windows Installer vs. Portable Edition

To accommodate varying retail IT policies and enterprise security environments, the desktop agent is distributed in two official binaries:

💡 Recommendation for the Portable Edition

10.5 Tab 3: Printer Assignment (Dual Windows Spooler & RAW TCP Socket 9100)

Nyxo Universal Printer features independent format routing tailored to document width and media type:

  • Thermal Ticket 80 mm (48 columns): Standard point-of-sale receipt width (3 inches). Accommodates tabular layouts with aligned columns (Qty, Description, Unit Price, Total). Perfect for checkout receipts and fiscal invoices.
  • Thermal Ticket 58 mm (32 columns): Compact format (2 inches). Employs vertical formatting (Qty x Item with total on the subsequent line) to prevent text truncation. Ideal for kitchen orders, barista tickets, or compact terminals.
  • A4 Document (Laser / Inkjet): Full sheet documents (210 x 297 mm) dispatched silently via integrated SumatraPDF, enabling vector PDF printing of invoices, reports, and delivery notes without dialogs.

B. Dual Architecture: Windows Spooler Drivers vs. RAW TCP Network Socket (Driverless)

  • Channel 1: Windows Spooler Printers: Dropdown auto-detecting installed Windows drivers (Termica, EPSON TM-T20, Bixolon, POS-80, etc.) injecting raw binary ESC/POS via winspool.drv.

Directly opens a TCP socket to hardware, transmitting ESC/POS in single-digit milliseconds and eliminating Windows spooler hangs.

11. Concurrency Control, Resilience & Lifecycle Events

11.1 Concurrency & Duplicate Prevention

In high-volume stores where multiple cashiers print simultaneously, PrintJobApiController::index() uses pessimistic row locking:

$jobs = DB::transaction(function () use ($node) {
    $pendingJobs = PrintJob::deliverable($node->id)
        ->lockForUpdate() // Row-level exclusive lock
        ->get();

    if ($pendingJobs->isEmpty()) return collect([]);

    PrintJob::whereIn('id', $pendingJobs->pluck('id'))
        ->update(['status' => 'processing', 'attempts' => DB::raw('attempts + 1')]);

    return $pendingJobs;
});

11.2 Orphan Job Rescue

If a workstation experiences power loss while printing, jobs remain stuck in processing. The deliverable() scope automatically rescues and re-queues any job stalled longer than config('nyxo-printer.timeout_minutes') (default 3 minutes).

12. Troubleshooting & Frequently Asked Questions (FAQ)

🔴 Why does my thermal printer output `%PDF-1.7` raw text?

Cause: A compiled PDF document was sent with content_type = 'escpos_base64'. Thermal receipt printers receive raw character streams and lack vector PDF engines.
Solution: Use ThermalBuilder or a PrintTemplateInterface. If you must print a PDF on thermal paper, configure format: 'ticket_80mm' and content_type: 'pdf_base64'; the desktop agent invokes SumatraPDF to rasterize it to paper width.

🔴 Error 401 Unauthorized behind Apache / FastCGI

Cause: Apache strips the Authorization: Bearer header by default on unencrypted local networks.
Solution: Add these directives to public/.htaccess:

RewriteEngine On
RewriteCond %{HTTP:Authorization} .
RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]

🔴 Clipboard copy fails in local LAN (`navigator.clipboard is undefined`)

Cause: Browsers disable navigator.clipboard on unencrypted HTTP domains.
Solution: Use a hidden DOM element fallback:

window.copyToClipboard = async function(text) {
    if (navigator.clipboard && window.isSecureContext) {
        try { await navigator.clipboard.writeText(text); return true; } catch (e) {}
    }
    const t = document.createElement('textarea');
    t.value = text;
    t.style.position = 'fixed'; t.style.left = '-9999px';
    document.body.appendChild(t);
    t.select();
    const ok = document.execCommand('copy');
    document.body.removeChild(t);
    return ok;
};

🔴 Laravel 13 `MissingAttributeException`

Cause: Laravel 13 activates Model::shouldBeStrict(true) by default.
Solution: Official models in nyxo-app/nyxo-printer are strictly sanitized to expose only validated physical columns.
